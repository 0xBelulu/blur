# Blur Community：构想摘要

> 状态：方向共识，非实现规格。P0 已上线，点云（P1）尚未开始。
> 前身是 [第一轮朋友实验](community-direction.md) 的话题讨论方案，该方案已主动放弃，原因见第一节。

## 一句话

**社区不是让人互相说话，而是让人看见自己在人群中的位置。**

## 一、我们明确不做的事

- 不做信息流、不做发帖、不做评论区
- 不做关注、粉丝、私信、@
- 不做点赞数、热榜、连续签到
- 不把用户生成的内容当作社区燃料

这不是克制，是算术：**任何一条 UGC 通道都会带来审核义务**。团队没有审核人力，也不应该在比赛周期里背这个包袱。第一轮方案（共同问题 + 接一句）正是卡在这里——它需要一个每天都在场的人，而这个人不存在。

## 二、那社区是什么

它不是一个空间，而是一个**分布**。

| 层 | 内容 | 状态 |
| --- | --- | --- |
| L0 | 一个人的测试结果 | 已上线 |
| L1 | 两个人之间的对比 | 已上线 |
| L2 | 所有人构成的一片场 | 待建（点云） |

L1 已经证明了这件事成立：两个人把画像放在一起，会自然产生"原来你是这样"的对话。L2 只是把"和一个人比"扩展成"看看我在所有人里的位置"。

**社区的价值不在互动，在参照。**

## 三、点云

机制：

1. 每份被主动设为公开的画像，取它的 10 维向量
2. 投影到二维（或三维）空间，成为场上的一个点
3. 点与点之间的距离，就是画像之间的相似度
4. 自己那个点高亮，其余点模糊、无标签

视觉上它应该像一片星尘，而不是一张散点图。这正好接上产品已有的光学场、水彩和模糊语言——**Blur 的社区看起来就应该是模糊的**。

交互边界（P1 只做这些）：

- 只读，不能点开任何一个点
- 不显示排名、不显示百分位、不显示"你超过了多少人"
- 不显示点的身份，即使你们是好友
- 自己的位置可以看，别人的位置只能感知密度

## 四、为什么这个设计成立

**1. 内容由引擎生成，不由用户生产。**
用户能输入的只有昵称和简介，两者都有长度上限。审核面从"无限文本"缩到"两个短字段"，这是数量级的差别。

**2. 匿名身份让"人肉"失去动机。**
系统里没有邮箱、没有手机号、没有 IP。即使有人想追究"那个点是谁"，也没有入口。

**3. 聚合优先，个体最小化。**
后台能看到人群的形状，看不到面具后面的人。这不是技术限制，是产品承诺。

**4. 分享即 opt-in。**
一个点出现，前提是本人主动把画像设为可见。默认不曝光，参与是选择的结果。

## 五、治理：现在不需要管理员，只需要一个开关

没有 UGC，就不需要 moderator。争议的对象不存在——没有人能发一段话让别人不舒服。

需要保留的最小能力，只有三件：

1. 昵称与简介的过滤（词表 + 长度）
2. 单条画像的下架能力（不是删账号）
3. 一个举报入口的占位，哪怕只是收件箱

开发者后台与社区管理员是两件事，将来若真的需要，也必须分开：

| | 开发者后台 | 社区管理员 |
| --- | --- | --- |
| 权力来源 | 系统所有权 | 社区规则授权 |
| 看什么 | 聚合指标 | 被举报的那一条 |
| 做什么 | 发布、迁移、修故障 | 下架、警告 |
| 失败模式 | 隐私越界 | 滥权 |

后台令牌独立于用户身份，数据库只存哈希，不设 `is_admin` 字段。这样即使某天交出审核权，交出去的也是"队列"，不是数据库。

## 六、度量：两个数字，两种口径

- **完成测试**：匿名计数，覆盖所有访客，包括从没注册的人
- **注册身份**：只有用过云端功能才产生，必然小于真实参与人数

两者永远不合并成一个"用户数"。后台只读、只聚合，规模数字走 5 分钟物化快照。

在答辩时，能解释清楚这两个数的差别，比数字本身更大。

## 七、风险，诚实列出

1. **点云会被读成排名。** 只要有位置，就有人问"我在前面还是后面"。文案与视觉必须持续否认优劣，只谈"位置"不谈"高低"。
2. **人少的时候像空房间。** 不造假数据、不显示虚构在线人数。空状态用"你是第 N 个点"承接，把稀少说成早期，而不是失败。
3. **小样本下匿名会被反推。** 朋友之间本来就互相知道彼此的结果，点云一旦显示身份就等于公开。所以不显示。
4. **分享链接是 bearer token。** 转发即公开，这是既有设计。点云入口要重申一次，不能让用户以为"进了点云才算公开"。
5. **二维投影会损失信息。** 两个人在平面上很近，未必真的相似。界面上应标明位置是近似，不给出精确距离。

## 八、路线

| 阶段 | 内容 | 新增的社交面 |
| --- | --- | --- |
| P0（已完成） | 结果、分享链接、好友、双人对比、只读后台 | 一对一的可见性 |
| P1 | 点云只读：匿名聚合、不可点开、自己高亮 | 一对多的"被看见" |
| P2 | 时间维度：最近 7 天新增的点、场的生长 | 在场感 |
| P3（可选） | 极轻的表达，例如给自己的点写一句状态 | 需要重新评估审核成本 |

明确不做：信息流、私信、关注关系、推荐排序。

## 九、可以直接说的话

> 我们不做社交网络。社交网络要你生产内容，我们要你只是存在。
>
> 每个人做完测试，会成为一片星图上的一个点。你能看见自己在哪，也能感觉到别人在附近，但你看不清他们是谁。
>
> 这不是一个广场，是一片夜空。

## 十、判断它是否成立的信号

不看注册数，看这三件：

1. 有人主动把画像设为可见（opt-in 率）
2. 有人第二次回来看自己的位置（回访）
3. 有人把点云截图发给朋友（自传播）

如果三者都没有，说明"看见位置"这件事不足以构成社区，应该回到 L1，把双人对比做深，而不是加功能。
