# Blur 后端与部署

React/Vite 前端静态托管在 Cloudflare Pages；只有 `/api/*` 调用 Pages Functions，私有画像存入 D1。测试、生成结果和查看本机画像均不依赖后端。

## 用户流程

1. 完成测试：只保存本机快照，不上传。上云是两件互相独立、都要用户点一下的事：把身份存到云端，以及把某一份画像存到云端。
2. “设置”→“权限管理”：测试结果可选仅我可见或好友可见（默认），公开可见保留为暂未开放选项。换展示结果沿用该权限。
3. 其他历史记录可在记录管理中逐份同步；已有单份分享链接在权限管理中集中管理，继续支持原有查看与对比。
4. “停止分享”：云端副本保留，原链接失效。已有链接与个人空间可见范围独立生效。
5. “移除云端副本”：本机画像保留，云端内容清除、分享失效。若当前只有云端摘要，先下载并成功保存完整画像再删除云端。再次同步使用新的云端 ID。
6. “删除本机”或“清空本机画像”：不删除云端或停止分享。仅本机画像删除后无法恢复；同步未确认或有待处理云端操作时暂不能删除本机。
7. “设置”→“离开”：退出这台设备只清除本机凭证，本机画像留下并解除云端关联，之后可用恢复密钥回来；删除身份则清空云端画像与答案、停止分享和好友码，不可恢复。

“我的”显示各份记录的存储与分享状态，可以筛选记录。进入该页只读取身份和云端摘要，不会自动上传任何记录。摘要不含原始答案或完整画像，按需下载。

## 轻量身份与恢复

- 无需注册。访问“我的”或主动使用云端功能时，在本机生成随机访客身份。昵称选填，修改身份昵称不会批量修改旧分享的昵称。
- “保存身份 / 在另一台设备恢复”可显示、复制或下载恢复密钥。首次保存身份只注册身份元数据，不上传本机画像。
- 恢复密钥携带完整管理权限，只给自己保存；公开分享链接使用另一随机标识，没有管理权限。两者在 UI 中明确区分。
- 在另一台设备输入密钥：先验证身份和云端摘要，再切换。本机已有完整画像继续保留并解除原身份的云端关联，不会随恢复自动上传；原身份的云端数据仍需原密钥管理。恢复的记录最初仅有摘要，查看或对比时才下载完整内容。
- 仅在本机、从未同步的画像无法通过密钥找回。清理浏览器站点数据前，应保存需要的身份密钥，并主动同步想保留的画像。没有密钥和原浏览器身份，无法找回云端管理权限。
- 密钥通过 Authorization 请求头使用，不放进 URL 或应用日志；D1 仅保存凭证的 SHA-256 哈希。身份 ID 是哈希前缀，用于识别，不用于授权。
- 云端画像必须属于一个云端身份：没有身份时 `PUT /api/records/:id` 返回 409，客户端引导先存身份。这样每份云端数据都能用恢复密钥找回，也都能被幽灵清理覆盖——无主的画像行既找不回，也永远不会被清理。

## 退出与注销

没有密码，凭证本身就是账号，所以“注销”拆成两件事：

- **退出这台设备**：只删本机凭证与身份缓存，本机画像保留并解除 `cloudId/shareId/cloudOwner` 关联，成为纯本机记录。云端身份、好友和分享链接都不受影响，用恢复密钥可以回来。有待处理的云端操作时不允许退出。
- **删除这个身份**：`DELETE /api/account`（需 `{ confirm: "DELETE" }`）。先清空该身份的云端画像与答案、撤销分享，再把账号行改成墓碑：`deleted_at` 写入、昵称与简介清空、`portrait_id` 与 `friend_code` 置空、`public_id` 保留。之后同一凭证访问任何接口返回 410，旧设备的延迟上传也无法复活账号。好友关系保留 30 天并返回 `person.deleted`，好友侧显示“已注销”后可自行移除。

墓碑不是删除行，这是有意的：删行会让一次超时重试把账号重新建成一个新的 `public_id`。`0009_account_deletion.sql` 只新增可空列与索引，可以先于代码上线。

## 幽灵身份清理

幽灵身份指没有任何设备还能出示其凭证的账号行：清站点数据、无痕窗口、换浏览器、Safari 对 localStorage 的自动清理，以及创建到一半就离开。三档策略在 `server/ghosts.js`：

| 档位 | 判定 | 处理 |
| --- | --- | --- |
| 孤儿 | 30 天未活跃，从未有画像，也没有任何好友关系 | 直接删除 |
| 休眠 | 180 天没有任何设备访问，但仍有画像或好友 | 墓碑化：清空内容、停止分享、清空标识 |
| 过期墓碑 | 墓碑超过 30 天 | 连同好友关系一并删除 |
| 无主画像 | 画像没有任何 `accounts` 行，超过 30 天 | 直接删除：没有密钥能打开它，按账号遍历的清理也永远看不到它 |

入口是 `POST /api/admin/ghosts/purge`（沿用后台令牌，与用户身份无关），`dryRun` 默认 `true`。Pages Functions 没有定时触发器，所以用 `npm run ghosts:purge` 手动执行或由外部定时任务调用；不在请求处理里做 DDL。后台“现存身份”口径已排除墓碑，并单列待清理的幽灵数。

## 本地运行与测试

使用 Node.js 24（测试使用内置 SQLite）和 `npm install` 安装的依赖。

```powershell
npm run build
npm run db:migrate:local
npm run dev:full
```

默认打开 `http://127.0.0.1:18788`。本地 D1 数据在 `.wrangler/`，不会提交。修改前端后需要重新构建；需要热更新时另开 `npm run dev`，其 API 请求会代理到本地 18788。未启动后端时仍可测试与保存本机画像。

端口被占用时，可用其他端口启动，例如 `npm run dev:full -- --port 18790 --inspector-port 19335`；此时 Vite API 代理目标也需相应调整。

```powershell
npm run lint
npm test
npm run build
npm run test:runtime -- http://127.0.0.1:18788
```

`npm test` 使用真实 SQLite 执行生产 SQL，覆盖身份隔离、私有字段隔离、显式同步、断网待确认、幂等重试、云端删除保留本机、恢复身份和旧版本迁移。运行时测试只连接本地地址，用临时画像验证 Cloudflare/D1 接口与 React 组件渲染，不启动 GUI 浏览器。

## 数据、兼容与故障处理

- 每次测试保存不可覆盖快照：答案、画像、题目数、时间、评分和题库版本。旧快照不会被新算法重算。
- 云端 ID 与本机 ID 分开；同一身份同一本机 ID 最多一个有效云端副本。超时重试不会重复创建，删除后新副本使用新 ID。删除清除答案、画像与分享标识，只保留最小墓碑，防止旧请求恢复被删数据。
- 公开接口按嵌套字段白名单返回画像，不含原始答案、凭证与管理字段。公开范围包含叙事和隐藏潜能，开启分享前说明。已被别人读取的内容无法从对方设备收回。
- 所有 API 返回 `no-store`。新会话中的旧缓存显示“云端状态待核实”；核实失败不把缓存当作最新服务器状态。
- 无常驻后台上传。默认好友可见的展示结果在相关页面进入或测试完成时同步；其他记录仍需主动同步。删除、撤销待确认任务保留，用户可以手动重试。分享请求的响应丢失时显示“开启分享待确认”，可以核实或停止可能已开启的分享。恢复身份不会把另一个身份的本机结果自动带入云端。
- 后端失败不会阻止前端生成画像。分享读取失败时有重试和返回测试入口；可手动复制纯文字摘要，不会偷偷改成将完整画像放入 URL。
- `shared/profile.js` 定义公开字段与快照版本。不兼容的评分或题库变化需更新版本；双人对比要求两者版本都相同，不生成关系匹配百分比。

## 控制台与接口

Cloudflare Workers & Pages 查看请求量与实时日志；D1 控制台查看 `accounts`、`profiles`。应用日志记录请求 ID、资源类型、方法、状态和耗时，不记录答案、密钥、分享标识或完整 URL。错误响应和响应头 `X-Request-Id` 可用于排查。503 时先检查 DB 绑定和迁移，再检查配额。

私有接口要求 `Authorization: Bearer <访客凭证>`；公开画像例外。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/account` | 读取身份，不自动注册；兼容旧匿名身份 |
| POST | `/api/account` | 注册身份或保存昵称，不上传画像 |
| GET | `/api/records?summary=1` | 私有列表摘要，不含完整画像与答案 |
| GET | `/api/records` | 完整私有列表，保留旧客户端兼容 |
| GET | `/api/records/:cloudId` | 本人下载一份完整画像 |
| PUT | `/api/records/:cloudId` | 幂等创建快照；`localId` 关联本机记录 |
| DELETE | `/api/records/:cloudId` | 清除云端内容并停用分享 |
| POST | `/api/records/:cloudId/share` | 开启或复用分享，提交可选昵称 |
| DELETE | `/api/records/:cloudId/share` | 停止分享 |
| GET | `/api/shares/:shareId` | 无需身份的公开只读画像 |
| POST | `/api/metrics/event` | 匿名计数，仅接受 `test_started` / `test_completed` |
| GET | `/api/admin/stats?days=30` | 后台聚合统计，需要独立后台令牌 |

## 管理员面板与流量口径

入口是 `#admin`，页面不在导航中出现。它只读，只显示聚合数量与按日趋势，不读取答案、画像正文、好友关系边、凭证或单用户记录。

访问令牌与用户身份体系完全分离：`admin_tokens` 只保存令牌的 SHA-256，用户凭证即使泄露也无法进入后台，也没有可被提权的 `is_admin` 字段。

```powershell
npm run admin:token                          # 生成令牌，打印写入本机/线上数据库的命令
npm run admin:token -- --apply local         # 生成并写入本机 D1
npm run admin:token -- --apply remote        # 生成并写入线上 D1
```

令牌只在生成时显示一次，数据库无法还原；丢失后重新生成即可。表为空时接口返回 503 而不是默认放行。页面把令牌存在当前标签页的 `sessionStorage`，关闭标签即失效。

两类数字必须分开看，不要混为一个“用户数”：

- **完成测试 / 开始测试**：匿名计数器，覆盖所有访客，包括从未使用云端功能的人。数据在 `metrics_daily`，按 UTC 日聚合，只有 `day / metric / count` 三列，没有任何可识别字段。客户端用 `sendBeacon` 发送，失败静默，不阻塞测试流程。
- **注册身份 / 云端画像 / 分享中 / 好友关系**：来自 `accounts`、`profiles`、`friendships` 的聚合。注册是懒发生的，只有访问“我的”、保存身份、同步画像或加好友时才创建账号，因此这个数一定小于真实参与人数。

`accounts.last_seen_at` 由 `0006_metrics.sql` 增加，最多每 24 小时写一次，写入失败会被忽略，不影响身份读取。活跃数据从该版本上线后开始累积，此前的身份没有历史，面板会显示起始日期而不是把空值当作 0。

规模数字不是每次现算。`0008_stats_snapshots.sql` 增加 `stats_snapshots`，每个 UTC 日一行，保存聚合结果与 `computed_at`：读取时若快照在 5 分钟内，直接返回该行；否则重算一次并覆盖。因此一次后台刷新的成本是常数（1 行快照 + 30 天趋势），而不是随身份数线性增长，代价是规模数字最多滞后 5 分钟，接口用 `cached` 标明本次是否来自快照。同一迁移补了 `accounts_created` 与 `accounts_last_seen` 两个索引，让新增趋势和活跃区间只读命中的行。快照只存计数，不含身份、答案、画像内容或好友关系。

匿名计数没有身份，也就无法去重或防刷，只适合作产品指标，不适合作为审计数据。需要更严格口径时应引入 Cloudflare Turnstile 或服务端事件，而不是在计数器上补身份。

发布顺序：先 `npm run db:migrate:remote` 应用 `0006_metrics.sql`、`0007_admin_tokens.sql`，确认 `npx wrangler d1 migrations list blur --remote` 无待执行项，再部署依赖它们的代码。`0006` 是增量迁移，旧代码可继续运行；`last_seen_at` 的写入已做容错，代码先于迁移上线也不会让身份接口报错。
