# Blur：个人空间与好友对比

本轮范围：完善个人记录、个人 profile、显式身份创建、好友关系和双人对比。现已接入正式页面和 API，`0003_people.sql` 已通过本地及生产 D1 迁移；生产迁移于 2026-10-18 补齐，并验证线上账户与好友相关接口。`design/profile-preview.html` 保留为隔离的视觉样张，不连接真实身份或数据。实际接口及状态约定见 [identity-friends-api.md](identity-friends-api.md)，发布与本次故障记录见 [backend.md](backend.md)。

## 产品边界

- 首次进入即可测试、查看结果和保存本机记录。
- 创建身份无需邮箱或密码，沿用当前随机凭证与恢复机制，显式填写展示名字；简介可选。
- 常用浏览器记住身份。换设备需要恢复凭证；原浏览器身份和凭证都丢失时无法找回，界面应如实说明。
- 注册不批量上传历史；当前展示结果默认同步给好友。测试结果范围在统一「权限管理」中调整，选画像沿用权限。
- 好友码或邀请链接默认直接建立好友关系，可在权限管理中开启手动确认。暂不做全站人员搜索。
- 旧的画像分享、对比链接继续工作，公开链接与好友权限独立管理。
- 社区动态、私信、推荐算法和多人空间留在当前范围之外。

## 设计先行的验收对象

先打磨一页具有完整交互状态的个人空间，再将同一套语言与布局用于其他页面。

用户已通过实际页面截图认可这版的气质，作为后续视觉基准：暖灰底色、淡水彩、克制的光学层次、舒展留白和日常文字。此认可针对视觉方向；真实数据、权限与其他交互状态继续按各自验收要求验证。

样张使用实际项目的色彩、氛围组件和原型内容。示例人物、日期与记录明确标注，和用户数据隔离；切换画像、编辑资料和改变可见性仅改变内存状态。

设计目标：

- 先看到名字、本人写的话和展示画像，再进入存档管理。
- 个人资料像日常介绍，容得下普通表达与幽默。关键操作使用直白名称。
- 视觉承接现有暖灰底色、水彩与轻微光学层次。动效承担过渡，不阻塞操作；支持减少动态效果。
- 身份凭证、删除、同步状态等管理信息按需要展开；真实产品的错误和未确认状态仍要清晰可见。
- 分别审看桌面与窄屏，并验证键盘、弹窗和长内容。

## 数据对象与权限

### 身份和公开标识

保留现有匿名凭证与 `accounts`，避免先重写登录系统。新增独立、随机的公开用户标识与好友码，不把恢复密钥或凭证散列前缀当作好友码。

显示名字允许重复，公开用户标识负责定位。创建身份应复用当前已持有的身份，重复提交保持幂等。

恢复另一个身份继续沿用现有本机记录保留规则，不静默合并好友关系或上传本机画像。账户恢复需要能找回云端 profile 与好友关系；仅存本机的记录仍需另行保管或主动同步。

身份创建页展示名字与可选简介，说明浏览器记忆与恢复规则，提供保存凭证引导和已有身份的恢复入口。允许稍后备份；添加好友时再次提醒尚未保存凭证的用户。

### 个人 profile

一个人拥有一份可编辑的 profile，与不可覆盖的测试快照分开。建议包含：公开标识、好友码、显示名字、简介、选定画像的云端 ID、好友可见性。

展示结果默认好友可见，首次同步自动完成；选画像不再重复要求勾选授权。新测试只新增快照，不自动替换已有明确展示选择。仅我可见、好友可见和未来公开可见的入口集中在权限管理。

如果选定的云端画像被删除，朋友端显示尚未展示画像，不自动使用其他记录替补。简介持久化到云端；目前 `saveBio()` 仅写本机，需要补齐接口和跨设备读取。

### 测试记录

继续使用现有不可覆盖快照及评分、题库版本；记录属于具体身份。好友只能读取本人明确选定且允许好友访问的画像投影，不能列举完整测试历史或获取原始答案。

公开分享继续使用现有 `share_id` 和公开字段白名单。好友授权走独立的本人/好友权限检查，不依赖用户先生成一个公开链接。

### 好友关系

好友关系连接稳定身份。关系用无序用户对唯一约束防止重复，保留申请发起者；状态至少区分待接受和已接受。

- 接受者必须是该申请的目标身份。
- 已接受关系中的任一方可删除关系，好友授权随即失效。
- 拒绝、取消与交叉申请的结果要有明确、幂等的约定。
- 自己加自己、重复申请、未知好友码和关系已解除等情况，返回可理解的状态。
- 好友码查询只返回确认邀请所需的最小资料，不返回私有记录或管理信息。

待接受申请不获得好友画像权限。客户端隐藏按钮不能替代服务端权限检查。

## 对比的第一版范围

入口从好友列表与好友个人页发起；读取双方主动展示且授权的画像。检查评分与题库版本兼容，复用现有维度对比和可视化。

首轮优先打磨共同倾向、差异、场景化解释及小屏阅读，沿用现有结果数据，避免生成未经依据支持的关系结论。具体答案不在好友投影中，逐题对照和共同答题需要另行设计明确授权。

一方尚未展示画像、收回权限、解除好友或网络失败时，各自显示对应状态。当前设备已取回的内容无法通过服务端撤销远程清除；刷新和后续请求重新检查权限，应用不把失效缓存当作最新状态。

## 页面与模块

先保留当前 React/Vite/Cloudflare Pages + D1 技术栈。评估并扩展现有 hash 路由，支持个人页、好友页与对比页的直接进入和刷新；本轮没有先迁移框架的必要。

- 入口：首次用户可直接测试；本机已有记录时给个人空间清楚入口。
- 我的：profile、历史记录、身份与备份，管理项按需展开。
- 创建/恢复身份：保留原页面上下文，完成后返回未完成的好友操作。
- 好友：列表、申请与查找好友码、好友资料。
- 对比：新好友入口与旧链接入口共用展示层，各自遵循自己的授权方式。

前端把记录与云端状态、身份、好友请求分模块，不把所有异步逻辑继续塞进 `App.jsx`。后端新增好友和 profile 处理模块，共用鉴权与公开投影；已有存档接口保持兼容。

数据库以 `0003_people.sql` 增量扩展。账户、好友和授权投影在 `server/people.js`，前端身份写入在 `cloud.js`，好友与画像选择在 `people.js`。页面保留 hash 路由，不新增路由框架。

## 实现顺序与验收

1. 设计样张：看清个人空间的气质、信息层次和核心交互，迭代到可以作为实现依据。
2. 身份与 profile：增量数据库迁移、显式创建与恢复、简介同步、选定画像；兼容旧账号与存档。
3. 好友：申请、接受、解除与权限；支持两份真实身份在不同会话中完成往来。
4. 对比整合：好友入口、授权读取、版本与缺失状态、对比体验打磨。

每步独立验证后再进入下一步。数据库迁移先在本地 D1 执行；现有 SQLite 接口测试覆盖新权限，保留全部旧测试；生产迁移另行执行，不在设计阶段触碰线上数据。

必须验证：

- 访客本机结果不上传；已创建身份按统一权限同步当前展示结果，其他历史不批量上传。恢复身份不自动上传另一身份的本机结果。
- 创建身份后原记录、原分享链接仍可用；恢复过程不覆盖本机数据。
- 非好友、待接受申请、已删除关系都无法读取好友画像。
- 停止公开分享不会改变好友权限；删除好友不会自动停止公开分享。
- 重复请求、超时与跨身份异步响应不会错误创建关系或改写当前身份。
- 数据库不可用或离线时保留本机体验，云端操作不显示虚假成功。
- 未创建身份、无记录、无好友、无展示画像、权限撤回等空状态都有可走通的入口。
