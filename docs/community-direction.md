# Blur Community：第一轮朋友实验

> 此文保留为早期讨论记录，不作为当前开发计划。当前已收敛为个人空间、轻量身份、好友与双人对比，见 [当前架构草案](identity-friends-architecture.md)。运营实验与社区动态均已后置。

状态：产品方向草案，尚未实现社区功能，也尚未邀请或收集参与者。第一批对象已经确定为身边的朋友和同龄人；下面的主题、规模与节奏是待验证的设计假设。

## 这次号召是什么

**邀请一小圈朋友，借几个有意思的问题，看见彼此平时没说过的那一面。**

Blur 的测试负责打开话题，社区让话题抵达另一个人。测试可以保留它不精确、带一点幽默的表达；人可以补充、反驳，也可以随时改变对自己的描述。画像提供一个开场，之后由本人接着说。

面向参与者的一句话：

> 不必一次把自己说清楚。来这里，认识朋友的另一面。

面向面试的一句话：

> 我正在用 Blur 发起一次小规模社区实验：看看一份人格画像和几个共同问题，能不能让朋友之间发生平时不会发生的对话。

这句话描述正在尝试的事。等实验有了真实记录，再补充参与人数、对话和回访情况。

## 第一次来到这里，会发生什么

以一位收到朋友邀请的人为例：

1. **先看到邀请者和一个共同问题。** 页面说清楚这是一个怎样的小圈子、大家在聊什么。可以先看活动介绍，加入圈子后再看成员内容；测试放在可选入口里。
2. **用一句话出现。** 选一个展示名字，回答本期问题。已有画像的人可以主动附上一份画像的简短名片；没有画像也可以参与。
3. **遇到一个具体的人。** 看见朋友的回答，愿意的话接上一句自己的经历。点进名字可以看到对方主动展示的介绍与画像。
4. **回来接着聊。** 再次进入时，先看到有人接过自己的哪句话，并能直接回到那段对话。第一轮通过原有朋友群人工提醒，产品内保留“给我的回应”入口。

第一次体验需要完成的闭环是：**我说了一句 → 有人接住 → 我想知道对方为什么这么说 → 我回来继续。**

首次参与可以只看；回复和附上画像都不作为加入条件。

一个示意场景，以下人物与内容仅用于说明设计，不作为上线的真实用户内容：

> 本期问题：朋友临时取消约定，你的第一反应是什么？
>
> A：嘴上说没事，其实已经在怀疑自己是不是太无聊了。
>
> B 回复 A：我取消约定经常只是没电了。看到这句，感觉以后得多解释一句。

这里的趣味来自同一件事在不同人心里的样子。回答可以轻松，也可以认真，不必要求参与者讲很私密的故事。

## 第一版围绕三个地方展开

| 地方 | 参与者看见什么 | 可以做什么 |
| --- | --- | --- |
| 我们这里 | 发起人的短邀请、本期一个问题、圈内成员的真实回答 | 加入后写一句，点开一段对话 |
| 一个人 | 展示名字、本人写的介绍、主动附上的画像名片 | 认识这个人；双方有兼容画像时进入现有对比 |
| 给我的回应 | 别人接过自己的话，以及原来的上下文 | 回到对话，继续回复 |

第一版的话题由发起人发布，每期只保留一个主问题。每人每期一条主回答，可修改或删除；回答下面使用一层文字回复，用回复对象标识接的是谁。先让这个规模可以被维护，再根据真实使用决定是否开放自由发题。

建议先试三个问题，各有不同的入口：

- **轻松开场：**朋友临时取消约定，你的第一反应是什么？
- **联系画像：**这份画像里，哪一句你最想补上“但其实……”？没有画像也可以聊一个别人对你的误判。
- **走向关系：**你希望朋友在什么时候主动找你，什么时候让你一个人待着？

这些都是新设计的社区话题，不自动读取或发布用户以前的测试答案。

## “有感觉”要落实到行为与界面

**人的话放在前面。** 卡片先展示“这个人说了什么”，名字、画像符号与原型作为辅助信息。简介可以写此刻的自己，不必写成一份稳定的人设。

**让回应有内容。** 主要动作叫“接一句”。输入提示可以是“这让我想到……”，不预先替用户生成一段认同。首版集中做文字回应，暂缓点赞计数、热榜、粉丝数和连续签到。

**保留轻松的余地。** 话题容得下玩笑、犹豫和矛盾。允许“我也说不清”，允许后来改口；界面不把参与描述成自我成长任务。

**让画面跟着人与人的往来变化。** 复用 Blur 的暖色水彩、留白、符号和克制的动效。有人回复时，清楚显示那个人和那句话；空圈子则由发起人的真实开场填起来，不用虚构头像、在线人数或示例动态制造热闹。

**保持相遇的开放性。** 第一轮让人通过回答认识彼此。原型和维度对比放在对话之后，不用人格相似度决定谁值得被看见，也不把一种原型固定成一个社群身份。

## 用一周试出它有没有生命力

以下人数与节奏只是首轮试验的建议规模，不是增长预测。

- 邀请约 12–20 位愿意反馈的朋友。邀请文案说明会遇到其他参与者、内容对谁可见，以及可以删除自己的内容。
- 发起人先认真回答第一题，并邀请两三位朋友写下真实开场。所有内容都由本人发布。
- 一周内做三期话题，每期留出回应时间。发起人先照顾还没有回应的人，也观察哪些对话会在没有自己推动时继续。
- 提醒先通过现有朋友群人工完成；在产品里给出可以回到原对话的入口。文案在下面备好，本次不代发消息。
- 结束时问参与者：有没有更了解一个人？有没有哪句话想继续聊？如果没有提醒，还会因为什么回来？

第一轮记录最基本的事实，人数较少时同时报告人数和比例：

| 要观察的事 | 记录口径 | 用来判断什么 |
| --- | --- | --- |
| 有人愿意开口吗 | 邀请人数、加入人数、发过主回答的独立人数 | 共同问题与参与门槛是否合适 |
| 话有人接吗 | 收到至少一位其他成员文字回复的主回答数 / 主回答总数 | 开口之后是否得到回应 |
| 对话会继续吗 | 作者在收到回复后再次接话的对话数 | 回应是否产生继续交流的意愿 |
| 有人主动回来吗 | 在另一天重新参与的人数；结合简短访谈记录是否受提醒 | 哪种实际体验带来回访 |
| 社区依赖谁 | 分别记录发起人与其他成员发出的回复数 | 互动是否开始在成员之间发生 |

先用简单事件或人工记录收集这些数据，不为第一轮搭完整分析平台。没有观察依据的地方记为未知，不把刷新页面等同于自发回访。

如果大家愿意测、愿意发，却很少互相回应，下一步先调整话题、人数和发起人的参与方式。如果对话发生了但没人回来，优先访谈一次性参与者，确认是实验已经满足了需求，还是回到对话太困难。

## 现有代码能支持到哪里

| 已有能力 | 代码位置 | 社区化时的边界 |
| --- | --- | --- |
| 轻量身份与恢复 | `src/utils/identity.js`、`server/api.js`、`migrations/0002_accounts.sql` | 可复用身份认证；需要新增圈成员关系与访问检查 |
| 昵称编辑 | `src/pages/My.jsx`、`src/utils/cloud.js` | 已注册身份可保存云端昵称；未注册时先本机保存。需要定义社区名字与旧分享昵称的关系 |
| 个人简介 | `saveBio()`，位于 `src/utils/cloud.js` | 当前仅写本机账户信息，数据库尚无简介字段，不能当成跨设备或对外展示能力 |
| 私有画像同步 | `src/utils/cloud.js`、`server/api.js` | 可以复用存储；同步仍只表示保存私有副本 |
| 分享画像 | `src/pages/SharedProfile.jsx`、`shared/profile.js` | 当前是持有链接可读。加入社区需要另外选择展示范围，不能把已有分享自动收录为成员资料 |
| 双人对比 | `src/pages/Comparison.jsx`、`src/utils/comparison.js` | 可复用兼容画像的维度对比；公开接口不含原始答案，不能据此展示朋友的同题作答 |
| 页面切换与视觉 | `src/App.jsx`、`src/components/optical/`、`src/index.css` | 可沿用现有页面状态机与视觉体系；新增固定背景页面遵守 `min-h-[100svh]` 约定 |

主体验的开发顺序：

1. **圈子与成员。** 增加邀请加入、成员身份与读取权限；先支持一个试点圈子，数据结构保留圈子归属。邀请链接用于加入，圈内内容由服务端核验成员后返回。
2. **共同问题与回答。** 发起人维护本期问题，成员提交、修改和删除自己的短回答；成员列表从真实数据产生。
3. **接一句与回来看。** 增加一层回复和“给我的回应”，让两台设备上的两个人能够完成往来。
4. **可选画像名片。** 成员选择哪一份画像、哪些简介内容用于圈内展示。给出清楚的预览与撤下入口；原始测试答案继续留在原有私有范围。

首版暂缓私信、关注关系、推荐排序、多圈运营与系统推送。删除权限、基础频率限制，以及发起人隐藏不合适内容的能力，应随真实发布功能一起完成，控制在这个小圈子的需求内。

这份方案的实现验收应包含：两位成员能看到同一问题、分别回答、相互回复并在刷新后找回；非成员无法读取圈内内容；本人能够编辑或删除自己的内容；未选择展示的画像和原始答案不会进入社区响应。后端不可用时明确显示失败，不把本机草稿显示成已发布。

## 可以直接使用的第一轮邀请文案

> 我在把 Blur 慢慢做成一个朋友之间的小地方，想邀请你来试一周。
>
> 我们会聊三个问题。你可以写一句自己的回答，也可以接一接朋友的话；想做测试的话，也能带着画像来。
>
> 第一题是：朋友临时取消约定，你的第一反应是什么？
>
> 我有点想知道，我们这些认识的人，会不会在同一件小事上想得完全不一样。
>
> 写下的话会被这个圈子里加入的朋友看到，你可以修改或删除自己的内容。测试画像由你主动选择是否展示。
>
> 还在很早期，也欢迎你直接告诉我：哪里有意思，哪里没感觉。

这段文案应在对应的成员权限与删除能力实现后使用。对外发布前附上真实的加入入口，不使用现有画像分享链接冒充社区入口。

面试时可以展示：这次邀请、几段经参与者同意引用的真实往来、参与与回访记录，以及由此改变的一项产品决定。社区是否成立，留给实际参与发生的事来回答。
